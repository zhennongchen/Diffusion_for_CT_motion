# Diffusion-based generative model for CT motion correction
**Author: Zhennong Chen, PhD**<br />

This is the GitHub repo based on a published paper: <br />
*Portable Head CT Motion Artifact Correction via Diffusion-based Generative Model* [link](https://www.sciencedirect.com/science/article/pii/S0895611124001551)<br />
Authors: Zhennong Chen, Siyeop Yoon, Quirin Strotzer, Rehab Naeem Khalid, Matthew Tivnan, Quanzheng Li, Rajiv Gupta, Dufan Wu<br />

**Citation**: Chen, Zhennong, et al. "Portable Head CT Motion Artifact Correction via Diffusion-based Generative Model." Computerized Medical Imaging and Graphics (2024): 102478.

## Description
We have proposed HeadMotion-Elucidated Diffusion Model(HM-EDM), to reduce the motion artifact in 3D head CT scans.<br />
The main contributions of HM-EDM are as follows:<br />
(1) first diffusion-based generative model to tackle the motion artifact in CT, suppress performance aginst CNN-based methods.<br />
(2) utilize [Elucidated Diffusion Model framework](https://github.com/NVlabs/edm) for better performance and faster sampling. Introduce histogram equalization in the image pre-processing to balance the performance in brain tissue and skull. <br />
(3) trained on simulated CT scans (simulated motion on motion-free fixed CT images using portable CT scan geometry) and validated on real-world portable head CT scans.<br />


## User Guideline
### Environment Setup
The entire code is [containerized](https://www.docker.com/resources/what-container). This makes setting up environment swift and easy. Make sure you have nvidia-docker and Docker CE [installed](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html#docker) on your machine before going further. <br />
- You can build your own docker from the folder ```docker```. <br />

### Data Preparation (we have examples available!)
- **Data Preprocessing**<br />
    - step 1 - format convert: you need convert DICOM files to Nii files, please do so using your own code  <br />
    - step 2 - pixel resampling: specifically the model input has uniform pixel size = [1,1,2.5]mm. please do so using your own code. it is recommended that you down-sample to this pixel size by averaging adjacent pixels/slices.
    - step 3 - training data simulation: you want to have paired motion-free and motion-corrupted image (generated by FBP) for training purpose. If you need to simulate motion-corrupted image, please use ```motion_simulation/portable_CT_motion_simulator.py``` <br />
        - To run the code successfully, you need to download the [CTProjector](https://github.com/wudufan/CTProjector) for some function support. Note that the simulation were done on the static image with pixel size = [1,1,1]mm (so that we have enough z information) and then resample to [1,1,2.5]mm. <br />
        - If you use our simulation, please cite [Chen et al.](https://aapm.onlinelibrary.wiley.com/doi/abs/10.1002/mp.17047).
    
- **Example Data**: we have prepared two example data (preprocessing done) in ```github_example_data```. **case_A** is a training simulated data with reference (motion-free) and simulated (motion-corrupted) images. **case_B** is a real-world testing case with only motion-corrupted image.

- **Patient list** <br />
    - Please prepare a patient list following my format in ```patient_list.xlsx```. This saves the data paths for all patients. It's easy to do so please prepare by your own code<br />

### Model and Experiments
use ```main_train.ipynb``` to train the model.  <br /> 
use ```main_predict.ipynb``` to do the motion correction on new data <br />
